Créer des composants

Un composant (ou module) consiste à créer des fichier css séparés pour créer des éléments réutilisables afin de créer une bibliothèque.

Cela évite principalement d'avoir à copier / coller une suite de classes Tailwind pour que tous les éléments semblable d'une page aient le même style.

Il faut créer tout d'abord un fichier d'input pour Tailwind, dans lequel on va au choix prendre tout le CSS de base de tailwind ou comme dans l'exemple suivant une partie des éléments. 


// Structure des fichiers dans ce projet
src/
 ├── css/
 |    └── cs-style.css          // Fichier de sortie généré par Tailwind
 |
 └── tailwind/                  // répertoire des fichiers a compiler pour la sortie
       ├── components/          // répertoire des composants réutilisables
       |    ├── buttons.css     
       |    ├── navigation.css 
       |    └── typography.css
       └── cs-input.css         // fichier principal de création du fichier de sortie
//

Une fois tous les fichiers créés, il faut écrire les composants en CSS en utilisant @layer, qui permet de créer des classes réutilisables.

En CSS, @layer (les calques de cascade) sert à contrôler l'ordre de priorité de vos règles CSS sans avoir à utiliser !important ni à vous soucier de la complexité des sélecteurs.

Imaginez-le comme une pile de feuilles transparentes : la feuille posée tout en haut l'emporte toujours sur celles du dessous, peu importe la longueur ou la précision du sélecteur écrit dessus.

Comme il faut essayer de réutiliser l'écosystème de Tailwind, on peut implémenter dans ces classes maison les classe déjà prêtes de Tailwind grace à @apply

@apply est une directive de Tailwind qui permet de regrouper plusieurs classes utilitaires (comme flex, bg-blue-500, p-4) à l'intérieur d'une classe CSS classique.

C'est un raccourci pour éviter de répéter la même longue liste de classes utilitaires dans votre HTML. 


// buttons.css
@layer components {
    .btn-primary{
        @apply 
            px-4 py-2 rounded font-bold 
            bg-blue-600 text-white 
            transition duration-200
            hover:bg-blue-700
            ;
    }

Intégrer les composants

Pour Intégrer les composants, il est possible de créer le fichier d'entrée avec seulement quelques éléments de Tailwind plutôt que toute la structure.

Au lieu d'utiliser @import "tailwindcss"; on utilisera : 


// fichier cs-input.css
@import "tailwindcss/theme.css"; /* les "fonctions" qui permettent de générer les éléments particulier de Tailwind */
@import "tailwindcss/preflight"; /* @tailwind base; */
@import "tailwindcss/utilities.css";

// intégration des fichiers de composants 
@import "./components/buttons.css";
@import "./components/navigation.css";
@import "./components/typography.css";
  1. tailwindcss/theme.css : Le socle des "Design Tokens" (Variables CSS)
    Ce fichier contient toutes les variables CSS par défaut de Tailwind (les couleurs comme --color-blue-600, les espacements, les tailles de police, les ombres, les points de rupture pour le responsive, etc.).
  2. tailwindcss/prefligh : Le reset CSS de base (anciennement @tailwind base;)
  3. tailwindcss/utilities.css : Le générateur de toutes les classes utilitaires (p-4, flex, etc.)

Extraire les composants

L'extraction de composant est une technique qui consiste à déplacer les classes utilitaires répétitives de votre HTML vers un fichier CSS dédié, en les regroupant sous une classe sémantique (ici, .navigation).

  1. Le HTML s'allège : Votre balisage n'est plus pollué par une longue suite de classes utilitaires (md:flex, flex-wrap, block, etc.). Il devient plus propre, plus lisible et se concentre uniquement sur la structure.
  2. Le CSS centralise la logique : Grâce au système d'imbrication (nesting) et à la directive @apply, vous ciblez directement les enfants (ul > li > a) depuis votre classe parente .navigation. Si vous devez modifier le design de votre barre de navigation plus tard, vous le faites à un seul endroit dans votre fichier CSS. 

// navigation.css
@layer components {
    nav.navigation ul{
        @apply md:flex flex-wrap justify-start mb-0;
        li{
            a{
                @apply block !ps-2 !pe-2;
            }
        }
    }
}

// composants.html
<nav class="navigation bg-gray-900 text-gray-50">
    <div class="container mx-auto p-2">
        <ul>
            <li class="hover:bg-gray-50 hover:text-gray-900">
                <a href="./index.html" title="installation et bases">Tailwind</a>
            </li>
            <li class="hover:bg-gray-50 hover:text-gray-900">
                <a href="./row.html" title="Le système lignes - colonnes">Lignes - Colonnes</a>
            </li>
            <li class="hover:bg-gray-50 hover:text-gray-900">
                <a href="./composants.html" title="Les composants de tailwind">Composants</a>
            </li>
        </ul>
    </div>
</nav>

Customisation avec les composants

cs-classes.css : Définition des composants sémantiques (@layer components).
Ce fichier sert à créer des classes personnalisées et réutilisables (comme .site-title).

  • Le principe : On y regroupe des classes utilitaires (@apply text-4xl font-bold) et/ou du CSS pur (line-height: 1.5;) sous un nom de classe unique. C'est idéal pour éviter de surcharger le code HTML avec de longues listes d'utilitaires pour des éléments globaux ou récurrents.

typography.css : Surcharge des balises HTML natives (@layer base)
Comme l'indique le commentaire, lorsque vous modifiez le comportement par défaut de balises HTML brutes (h1, p, code, pre), il est recommandé de les placer dans un bloc @layer base.

  • Le principe : C'est ici que vous redéfinissez le Preflight (le reset CSS de Tailwind). Vous appliquez des styles globaux à tous vos paragraphes, titres ou blocs de code sans avoir à ajouter de classes dans votre HTML. Les modificateurs ! (!important) et les valeurs arbitraires ([1rem]) y sont utilisés pour forcer ces comportements de typographie de manière cohérente à l'échelle de tout le site.

cs-input.css : Le fichier d'orchestration (Point d'entrée)
Ce fichier centralise l'ensemble de votre architecture CSS grâce à une approche granulaire :

  • Les briques de Tailwind : Il importe d'abord le dictionnaire de variables (theme.css), le reset de base (preflight), puis le générateur de classes utilitaires (utilities.css).
  • Vos modules personnalisés : Il intègre ensuite vos composants (buttons.css, navigation.css, cs-classes.css) et vos styles de base globaux (typography.css).
  • L'intérêt : L'ordre des @import est crucial. En plaçant vos fichiers personnalisés à la fin, vous garantissez que vos règles et vos composants ont la priorité et s'appuient correctement sur tout l'écosystème Tailwind.

@layer base vs @layer components

  1. @layer base est prévu pour les balises HTML brutes : C'est ici que l'on surcharge le Preflight (les styles par défaut des éléments h1, p, a, code sans classe).
  2. @layer components est réservé aux classes réutilisables : Il sert à définir des motifs d'interface nommés, comme votre .site-title (ou .btn, .card).
